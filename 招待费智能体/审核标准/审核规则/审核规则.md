# 业务招待费审核规则

> 本规则定义批次审核时的跨文档一致性校验标准。
> 每条规则对应一个校验检查项，实现时应记录规则编号、严重程度与判定依据。
> 所有字段名均为 MD 识别结果中的中文字段名。

---

## 规则1：金额一致性

**规则编号**: `金额一致性`
**严重程度**: 高
**标准来源**: 本文件 §1

### 要求
批次中所有识别出的 MD 文件的金额字段必须一致，以**发票大写金额**为唯一标准值。

### 校验逻辑
1. 从发票 MD 文件中提取 `价税合计（大写)` 字段的值，转为数字后作为标准金额
2. 提取以下文件中的金额字段，与标准金额逐一比对：
   - 业务招待审批单 — `招待金额`
   - 支付凭证 — 账单金额行（如 `-832.00`，取绝对值）
   - 支付证明 — `金额(元)` 列
   - 业务招待费报账单 — `发票金额` / `税额` 合计
3. 任一文件金额与发票大写金额不一致（容差 0.01 元），则判定为违规

### MD 字段映射

| 文档类型 | 金额字段 | 示例值 |
|----------|----------|--------|
| 发票 | `价税合计（大写)` | 捌佰叁拾贰圆整 |
| 发票 | `（小写）¥` | ¥832.00 |
| 审批单 | `招待金额` | 1050 |
| 支付凭证 | 账单金额行 | -832.00 |
| 支付证明 | `金额(元)` | 832.00 |

### 判定依据
发票大写金额具有最高法律效力，其他单据金额必须与之匹配。

## 规则2：日期一致性

**规则编号**: `日期一致性`
**严重程度**: 高
**标准来源**: 本文件 §2

### 要求
批次中所有文件的日期必须以**业务招待审批单的招待日期**为准。

### 校验逻辑
1. 从业务招待审批单中提取 `招待日期` 作为标准日期
2. 提取以下文件中的日期字段，与标准日期比对：
   - 发票 — `开票日期`（应在招待日期之前或同日）
   - 支付凭证 — `支付时间`（应在招待日期之后或同日）
   - 支付证明 — `交易时间`（应在招待日期之后或同日）
   - 活动函件 — `交流时间`（应与招待日期一致或前后 ±7 天）
3. 任何日期逻辑异常判定为违规

### MD 字段映射

| 文档类型 | 日期字段 | 示例值 |
|----------|----------|--------|
| 审批单 | `招待日期` | 2026-02-27 |
| 发票 | `开票日期` | 2026年02月27日 |
| 支付凭证 | `支付时间` | 2026年2月27日20:52:04 |
| 支付证明 | `交易时间` | 2026-02-2720:52:04 |
| 活动函件 | `交流时间` | 2026年2月27日 |

### 判定依据
业务招待审批单是费用发生的原始凭证，其招待日期为事件发生基准时间。

## 规则3：招待标准合规性

**规则编号**: `招待标准合规性`
**严重程度**: 高
**标准来源**: 本文件 §3 + `审核标准/政策法规/附件1：中国移动广东公司清远分公司业务招待费管理办法（V9.0）-2025年7月9日发布.docx` 第15-22条

### 要求
从业务招待审批单中提取招待人数、陪同人数、人均费用、招待金额，对照标准目录校验是否符合规定。

### 校验逻辑

#### 3.1 人均费用标准

| 人员级别 | 外事商务招待 | 其他公务招待 |
|----------|-------------|-------------|
| 省管中层 | ≤400元/人 | ≤200元/人 |
| 市管中层 | ≤300元/人 | ≤200元/人 |
| 其他人员 | ≤200元/人 | ≤150元/人 |

| 招待类型 | 标准 |
|----------|------|
| 内部业务招待（省管/市管中层） | ≤150元/人 |
| 内部业务招待（其他人员） | ≤100元/人 |
| 工作餐 | ≤60元/人 |

#### 3.2 陪同人数标准

**外部招待**:
- 招待对象 ≤5人：陪同人数 ≤ 招待对象人数
- 招待对象 >5人：陪同人数 ≤ 招待对象人数 + (招待对象人数 - 5) ÷ 2

**内部招待**:
- 招待对象 ≤10人：陪同人数 ≤ 3人
- 招待对象 >10人：陪同人数 ≤ 招待对象人数 ÷ 3

#### 3.3 其他标准
- 酒水单价：≤100元/瓶
- 纪念品：≤200元/人

### MD 字段映射

| 字段 | 来源文档 | 示例值 |
|------|----------|--------|
| `招待人数` | 审批单 | 5 |
| `陪同人数` | 审批单 | 2 |
| `人均费用` | 审批单 | 150 |
| `招待金额` | 审批单 | 1050 |
| `招待类型` | 审批单 | 其他公务招待 |
| `是否工作餐` | 审批单 | 否 |

### 判定依据
管理办法第15-22条，费用标准与陪同人数限制。

## 规则4：招待单位经营状态

**规则编号**: `单位经营状态`
**严重程度**: 提示
**标准来源**: 本文件 §4 + `审核标准/业务规范/业务招待费审查风险点.docx` 第8条

### 要求
从招待单位经营状态文件中提取招待单位名称后的关键文字，判断经营状态是否正常。

### 校验逻辑
1. 从业务招待审批单中提取 `招待对象` 字段作为招待单位名称
2. 在招待单位经营状态 MD 文件中搜索该单位名称（模糊匹配，取最关键词）
3. 找到后提取单位名称后面的 **10个字符** 作为经营状态描述
4. 判断是否包含 "正常" 字样：
   - 包含 "正常" → 经营状态正常，无需人工干预
   - 不包含 "正常" → 提取 **5个字符** 作为摘要，标记为需人工审核
5. 若未找到单位名称，标记为需人工审核

### MD 字段映射

| 字段 | 来源文档 | 示例值 |
|------|----------|--------|
| `招待对象` | 审批单 | 东信君达（清远）律师事务所 |
| 经营状态标题 | 经营状态 | 广东广信君达（清远）律师事务所正常 |

### 实际案例说明
审批单中 `招待对象` 为 "东信君达（清远）律师事务所"，经营状态文件中标题为 "广东广信君达（清远）律师事务所**正常**"。需要模糊匹配单位名称，然后判断紧跟其后的文字是否含 "正常"。

### 判定依据
风险点第8条，需确认招待单位经营状态是否正常。

## 规则5：支付凭证一致性

**规则编号**: `支付凭证一致性`
**严重程度**: 高
**标准来源**: 本文件 §5

### 要求
支付凭证与支付证明之间的关键字段必须一致。

### 校验逻辑
比对以下字段在支付凭证和支付证明中的值是否完全一致：

| 比对项 | 支付凭证字段 | 支付证明字段 | 示例值 |
|--------|-------------|-------------|--------|
| 交易单号 | `交易单号` | `交易单号` | 4200003000202602278733670901 |
| 商户单号 | `商户单号` | `商户单号` | 2026022720000007655413900311007 |
| 金额 | 账单金额行 | `金额(元)` | 832.00 |
| 商户全称 | `商户全称` | `交易对方` | 清远市清城区新城顺隆河鲜坊 |
| 交易时间 | `支付时间` | `交易时间` | 2026-02-27 20:52:04 |

### 判定依据
支付凭证与支付证明是同一笔交易的不同证明，所有关键字段必须匹配。

## 规则6：活动函件日期一致性

**规则编号**: `活动函件日期`
**严重程度**: 中
**标准来源**: 本文件 §6 + `审核标准/政策法规/附件1：中国移动广东公司清远分公司业务招待费管理办法（V9.0）-2025年7月9日发布.docx` 第11条

### 要求
所有 MD 文件中的日期必须与活动函件中记载的日期一致。

### 校验逻辑
1. 从活动函件 MD 文件中提取 `交流时间` 日期
2. 与批次中其他文件的日期字段比对：
   - 业务招待审批单 — `招待日期`
   - 发票 — `开票日期`
   - 支付凭证 — `支付时间`
3. 活动函件日期应在招待日期前后合理时间范围内（±7天）
4. 超出合理范围判定为异常

### MD 字段映射

| 文档类型 | 日期字段 | 示例值 |
|----------|----------|--------|
| 活动函件 | `交流时间` | 2026年2月27日 |
| 审批单 | `招待日期` | 2026-02-27 |
| 发票 | `开票日期` | 2026年02月27日 |
| 支付凭证 | `支付时间` | 2026年2月27日20:52:04 |

### 判定依据
管理办法第11条，往来公函应与实际活动时间匹配。

## 字段提取说明

审核规则从 MD 文件原文中提取字段，不使用英文字段名。提取方式：

1. **键值对匹配**: 如 `招待日期` 后面跟的值 `2026-02-27`
2. **表格单元格匹配**: 如审批单的表格中 `招待人数` 对应的单元格值 `5`
3. **正则表达式匹配**: 如金额大写转数字、日期格式标准化
4. **模糊文本匹配**: 如单位名称在经营状态文件中的搜索
