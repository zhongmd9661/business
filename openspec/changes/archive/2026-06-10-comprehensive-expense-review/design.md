## Context

制度文档包含约 40 条审查要点，涵盖单据完整性、金额标准、招待类型、禁止性规定、报销合规、交叉稽核六大类。现有 `ExpenseReviewer` 仅覆盖其中 6 条。新代码放在 `src/expense_review_comprehensive/`，不修改现有 `expense_review` 代码。

## Goals / Non-Goals

**Goals:**
- 实现覆盖全部制度审查要点的规则引擎
- 从 OCR 解析的 Markdown 文本中提取结构化审核字段
- 按规则类别分组输出审核报告

**Non-Goals:**
- 不修改 `src/expense_review/` 已有代码
- 不实现制度文档本身的 OCR 解析（仅审核被解析的业务招待费单据）
- 不提供数据库或 Web UI

## Decisions

- **独立代码包 `expense_review_comprehensive`**: 避免影响现有 reviewer 的调用方。引用 `Finding` 等基础类型，但不修改其定义
- **规则分类器模式**: 按制度类别（单据完整性、金额标准、招待类型、禁止性规定、报销合规、交叉稽核）组织规则，每个类别一个 checker 类
- **字段提取器**: 基于正则表达式的字段提取，从 Markdown 文本中提取金额、日期、招待类型、人员层级、供应商等结构化数据
- **金额标准矩阵**: 将管理制度中的人员层级 × 招待类型 → 金额上限的矩阵编码为查找表
- **报告分组**: 按规则类别展示命中情况，便于定位问题

## Risks / Trade-offs

- [OCR 质量导致字段提取失败] → 提取失败时标记为"提示"级别，不影响其他规则
- [制度规则存在模糊表述] → 以制度原文为准，对模糊规则标注为"提示"级别，由人工复核
- [交叉稽核需要多文档关联] → 跨文档检测（如重复招待、拆分报销）需要批量模式，单文档模式跳过
