## 一、系统概述

### 1.1 系统简介

**业务招待费智能审核系统** 是一款面向企业财务报销场景的智能化审核工具。系统通过 OCR 光学字符识别技术自动读取单据文档（发票、审批单、报账单、支付凭证等），提取关键字段，并根据企业管理制度自动执行多维度合规性审核，最终生成结构化审核报告。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| **智能 OCR 识别** | 支持 PDF、JPG、PNG、XML、DOCX、XLSX 等多种格式单据的自动识别 |
| **字段自动提取** | 从识别文本中自动提取金额、日期、人数、招待类型等 30+ 关键字段 |
| **规则自动审核** | 内置 34+ 条审核规则，覆盖单据完整性、金额标准、禁止性规定等 7 大类别 |
| **跨文档校对** | 自动比对发票、审批单、报账单之间的金额、日期一致性 |
| **批次聚合审核** | 同批次多张单据智能聚合，避免金额重复计算 |
| **审核报告生成** | 自动生成 Markdown 和文本双格式审核报告，标注问题严重级别 |
| **Web 在线操作** | 提供浏览器界面，支持文件上传、任务管理、报告查看 |

### 1.3 工作流程

```
┌─────────────┐      ┌──────────────┐      ┌──────────────┐      ┌────────────┐      ┌────────────┐
│  ① 上传文档  │ ──→  │ ② OCR 识别  │ ──→  │ ③ 字段提取  │ ──→  │ ④ 规则审核  │ ──→  │ ⑤ 审核报告  │
│  (PDF/图片)  │      │ (MinerU 引擎) │      │ (正则/LLM)  │      │ (34+条规则)  │      │ (在线查看)   │
└─────────────┘      └──────────────┘      └──────────────┘      └────────────┘      └────────────┘
```

### 1.4 系统要求

| 项目 | 最低要求 | 推荐配置 |
|------|----------|----------|
| 操作系统 | Windows 10 | Windows 11 |
| Python 版本 | 3.11 | 3.11+ |
| 内存 | 8 GB | 16 GB |
| GPU | 可选（无 GPU 使用 CPU，速度较慢） | NVIDIA GPU + CUDA 11.8（推荐 RTX 3060 及以上） |
| 显存 | - | ≥ 8 GB |

## 二、环境准备

### 2.1 检查 Python 版本

打开 PowerShell 终端，执行：

```powershell
python --version
```

确认输出为 `Python 3.11.x` 或更高版本。如未安装 Python，请从 https://www.python.org/downloads/ 下载安装。

### 2.2 创建虚拟环境

> **重要**：每次全新安装或首次使用时，**务必新建虚拟环境**，不要沿用旧项目遗留的 `.venv` 文件夹，否则 pip 会将依赖安装到错误的目录。

```powershell
cd "D:\00_项目\招待费智能体"

# 如已有旧 .venv 文件夹，先删除或重命名
# Remove-Item .venv -Recurse -Force

# 创建新虚拟环境
python -m venv .venv
```

创建后执行以下命令，确认 `command` 行指向当前项目路径（`招待费智能体`），而非其他目录：

```powershell
# 查看虚拟环境配置
Get-Content .venv\pyvenv.cfg
```

输出中 `command` 行应包含 `招待费智能体\.venv`，例如：

```
command = C:\...\python.exe -m venv D:\00_项目\招待费智能体\.venv
```

如果指向 `D:\02_ocr\.venv` 或其他路径，说明虚拟环境创建失败，请删除 `.venv` 后重新创建。

### 2.3 安装依赖

```powershell
# 激活虚拟环境
.venv\Scripts\activate

# ⚠️ 重要：激活后请确认 python.exe 指向虚拟环境（而非系统 Python）
python.exe -c "import sys; print(sys.executable)"
# 输出应包含 .venv，如不是请跳过 activate，直接使用 .venv\Scripts\python.exe

# 安装核心依赖（--no-cache-dir 避免缓存异常）
python.exe -m pip install --no-cache-dir -r requirements.txt

# 安装 Web 服务依赖
python.exe -m pip install --no-cache-dir -r requirements-web.txt
```

安装过程可能需要几分钟，请耐心等待。

> **注意**：安装完成后如果出现 `paddlex requires...` 的依赖冲突提示，不影响系统运行，安装以下缺失包即可修复：
> ```powershell
> python.exe -m pip install aistudio-sdk chardet ujson --no-cache-dir
> ```
>
> **常见缺失包**：首次安装时部分传递依赖可能未完整安装，如果启动时提示 `ModuleNotFoundError`，请强制重装对应包：
> ```powershell
> # 单个包
> .venv\Scripts\python.exe -m pip install --force-reinstall --no-cache-dir <包名>
>
> # 全部 Web 依赖
> .venv\Scripts\python.exe -m pip install --force-reinstall --no-cache-dir -r requirements-web.txt
> ```

### 2.4 下载 OCR 模型（首次使用）

```powershell
.venv\Scripts\python.exe scripts/download_models.py
```

模型文件会保存到项目目录下的 **`models/`** 文件夹中（约 22 GB）。下载后整个项目目录可以整体移动部署，**无需重新下载模型**。

模型已下载过的情况下，脚本会自动检测并跳过。可通过以下命令确认：

```powershell
# 查看项目目录下的模型文件夹
ls models\
```

> **注意**：
> - 如网络较慢，`.env` 中已配置使用 `modelscope`（国内镜像）下载，无需额外设置。
> - 如执行时提示 `ModuleNotFoundError: No module named 'modelscope'`，说明包文件不完整，强制重装即可：
>   ```powershell
>   .venv\Scripts\python.exe -m pip install --force-reinstall --no-cache-dir modelscope==1.37.1
>   ```

└── .env                              # 环境配置

### 3.2 配置文件说明

项目使用 `.env` 文件配置核心参数：

```ini
# 模型来源：modelscope（国内镜像）或 huggingface
MINERU_MODEL_SOURCE=modelscope

# GPU 设备：cuda（NVIDIA GPU）/ cpu（无 GPU 时使用）
MINERU_DEVICE=cuda
```

> **无 GPU 用户**：将 `MINERU_DEVICE` 改为 `cpu`，系统仍可运行，但 OCR 识别速度会明显降低。

```powershell
cd "D:\00_项目\招待费智能体"
.venv\Scripts\python.exe start_server.py --port 8006

```powershell

```

### 4.3 手动启动

```powershell
cd "D:\00_项目\招待费智能体"
.venv\Scripts\python.exe -m uvicorn src.web_service.app:app --host 0.0.0.0 --port 8006
```

### 4.4 启动过程说明

服务启动时会依次完成：

1. **初始化数据库** — 首次启动自动创建 SQLite 数据库和默认数据
2. **启动 MinerU OCR 引擎** — 加载 OCR 模型，首次启动约需 30-60 秒
3. **加载审核规则** — 从制度文档自动解析规则到数据库
4. **服务就绪** — 终端显示 "Uvicorn running" 即表示启动完成

> **提示**：启动期间访问页面可能短暂返回 503，等待引擎加载完成后即可正常使用。

## 五、使用指南

### 5.1 注册账号

首次使用需要注册账号：

1. 打开浏览器访问 `http://127.0.0.1:8006/ui-index`
2. 切换到 **"注册"** 标签页
3. 输入用户名和密码（密码需 6 位以上）
4. 点击 **"注册"** 按钮
5. 注册成功后切换到 **"登录"** 标签页，输入账号密码登录

### 5.2 上传单据文件

1. 登录后点击左侧菜单 **"文件上传"**
2. 将单据文件拖拽到上传区域，或点击区域选择文件
3. 支持批量选择多个文件
4. 点击 **"开始上传"**

**支持的文件格式：**

| 类型 | 扩展名 |
|------|--------|
| PDF 文档 | `.pdf` |
| 图片文件 | `.jpg`, `.jpeg`, `.png` |
| XML 文件 | `.xml`（全电发票） |
| Office 文档 | `.docx`, `.xlsx` |

**单文件大小限制：** 100 MB

### 5.3 查看任务状态

上传后系统自动进入 **"任务管理"** 页面，显示所有审核任务：

| 状态 | 说明 |
|------|------|
| 🟡 等待处理 | 任务已创建，排队等待 OCR 识别 |
| 🔵 识别中 | 正在进行 OCR 识别和字段提取 |
| 🟢 已完成 | 审核完成，可查看报告 |
| 🔴 失败 | 处理失败，可查看错误信息 |

> OCR 识别需要一定时间（单文件约 10-30 秒），请耐心等待。

### 5.4 查看审核报告

1. 在任务列表中点击 **"已完成"** 状态的任务卡片
2. 点击 **"查看报告"** 按钮
3. 报告以 Markdown 格式展示，包含：
   - 批次信息（文档数、部门、招待类型）
   - 总体风险判定
   - 各规则类别发现的问题
   - 每条问题的制度依据

### 5.5 查看字段提取结果

在任务详情页面点击 **"查看字段"**，可查看系统从各单据中提取的结构化字段，包括：

- 招待日期、发票日期、申请日期
- 发票金额、实际金额、人均金额
- 招待人数、陪同人数
- 招待类型、人员层级
- 招待单位、经办人
- 报账单号、发票号码等

### 5.6 删除任务

在任务详情页面点击 **"删除任务"**，将同时删除数据库记录和关联文件。

### 5.7 审核标准查询

点击左侧菜单 **"标准查询"**，可查看当前生效的招待费标准：

- 外部招待金额标准矩阵（人员层级 × 招待类型）
- 内部招待标准
- 工作餐标准
- 酒水单价上限
- 纪念品金额上限

## 七、审核规则说明

### 7.1 规则总览

系统内置 **34+ 条审核规则**，覆盖 7 大类别：

### 7.2 单据完整性（7 条）

| 规则 | 说明 | 严重级别 |
|------|------|----------|
| 报账单号一致性 | 发票、审批单、支付凭证上的报账单号应一致 | 提示 |
| 费用明细清单 | 必须附有费用明细清单 | 中 |
| 支付凭证 | 2024-04-01 后必须 100% 附带 | 高 |
| 支付流水证明 | 2025-09-01 后必须 100% 附带 | 高 |
| 往来公函 | 2025-12-04 后外部招待必须附带 | 高 |
| 发票查验 | 2025-06-01 前需手动查验证明 | 中 |
| 网格分摊表签章 | 分摊表需签章确认 | 低 |

### 7.3 金额标准（5 条）

**外部招待标准矩阵：**

| 人员层级 | 外事/商务 | 其他公务 |
|----------|-----------|----------|
| 省管中层 | 400 元/人 | 250 元/人 |
| 市管中层 | 300 元/人 | 200 元/人 |
| 其他人员 | 250 元/人 | 150 元/人 |

**内部招待标准：** 省管/市管中层 150 元/人，其他人员 100 元/人
**工作餐标准：** 60 元/人
**酒水单价上限：** 100 元
**纪念品上限：** 200 元/人

### 7.4 招待类型与陪同人数（3 条）

| 规则 | 说明 |
|------|------|
| 类型匹配 | 党政军机关→其他公务招待，内部单位→内部业务招待 |
| 外部陪同 | ≤5 人时对等，>5 人时超出部分不超过一半 |
| 内部陪同 | ≤10 人时上限 3 人，>10 人时上限 1/3 |

### 7.5 禁止性规定（6 条）

| 规则 | 说明 |
|------|------|

## 八、常见问题

### Q1：服务启动很慢怎么办？

服务启动时需要加载 MinerU OCR 引擎和模型，首次启动约需 **30-60 秒**。启动期间 API 会返回 503，等待终端显示 "Uvicorn running" 即表示就绪。

### Q2：没有 GPU 能否运行？

可以。将 `.env` 文件中 `MINERU_DEVICE` 改为 `cpu`，系统使用 CPU 运行 OCR。识别速度会比 GPU 慢 5-10 倍，但功能不受影响。

### Q3：上传文件后一直显示"等待处理"？

检查以下几点：
1. 服务是否正常启动（终端无报错）
2. MinerU 引擎是否加载成功（日志有 "MinerU engine started"）
3. 文件类型是否支持（仅支持 PDF、JPG、PNG、XML、DOCX、XLSX）
4. 文件大小是否超过 100 MB

### Q4：审核报告内容为空？

可能原因：
1. OCR 识别失败 — 检查文件是否清晰可读
2. 字段提取失败 — 检查文件格式是否规范
3. 所有规则均通过 — 若无问题则报告可能仅显示"无高风险"

### Q5：如何修改审核标准？

管理员用户可通过 Web 界面的 **"规则管理"** 页面修改标准，或通过 API 操作。普通用户仅可查看。

### Q6：端口被占用怎么办？

启动时指定其他端口：
```powershell
.venv\Scripts\python.exe start_server.py --port 8088
```

### Q7：局域网内其他电脑如何访问？

启动时终端会显示局域网 IP 地址。在局域网内其他电脑的浏览器中访问 `http://<本机IP>:8006` 即可。如无法访问，检查防火墙设置。

### Q8：如何停止服务？

在启动服务的终端窗口中按 **Ctrl + C** 即可停止。

### Q9：数据库文件在哪里？

数据库文件位于 `data/web_service.db`（SQLite 格式），首次启动时自动创建。

### Q10：测试材料运行后找不到了？

批量处理模式（CLI）下，`data/input/` 目录的材料在处理完成后会被移走。如需重复测试，请从 `01业务招待费材料案例/` 重新复制。Web 界面上传不受影响。

### Q11：提示 `No module named xxx`（模块未找到）？

`pip show` 显示已安装，但运行脚本时仍然报找不到模块，常见原因有两种：

**原因一：包文件不完整（pip 只记录了元数据，实际文件未写入）**

直接强制重新安装该包即可修复：

```powershell
# 强制重新安装指定包（以 modelscope 为例）
.venv\Scripts\python.exe -m pip install --force-reinstall --no-cache-dir modelscope==1.37.1

# 验证
.venv\Scripts\python.exe -c "import modelscope; print(modelscope.__file__)"
```

如果确认是此原因，建议全部重新安装以确保完整：

```powershell
.venv\Scripts\python.exe -m pip install --force-reinstall --no-cache-dir -r requirements.txt
.venv\Scripts\python.exe -m pip install --force-reinstall --no-cache-dir -r requirements-web.txt
```

**原因二：pip 把包安装到了错误的虚拟环境**

排查步骤：

**1. 确认 Python 实际路径**

```powershell
.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
.venv\Scripts\python.exe -m pip show <包名>
```

查看输出中的 `Location` 是否指向当前项目目录下的 `.venv\Lib\site-packages`。如果指向其他路径（如 `D:\02_ocr\.venv\...`），说明包被安装到了别处。

**2. 检查 pip 全局配置**

```powershell
cat $env:APPDATA\pip\pip.ini
```

如果文件中存在 `target` 配置指向其他目录，请删除该配置行或整个文件。

**3. 删除旧虚拟环境并重建（推荐）**

```powershell
cd "D:\00_项目\招待费智能体"
Remove-Item .venv -Recurse -Force
python -m venv .venv
.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements.txt
.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements-web.txt
```

## 十、审核管理功能（v0.3.0 新增）

### 10.1 功能概述

审核管理功能为每条提交记录（流水号）建立完整的审核链路：

```
提交记录 → OCR 文件上传(9槽位) → OCR 识别 → 字段提取 → 6条规则审核 → 审核报告
```

### 10.2 使用流程

**第一步：提交招待费记录**

在主页或审核页填写并提交招待费信息，系统自动生成流水号（如 `ZDF-20260728-0001`）。

**第二步：进入审核详情页**

访问 `http://127.0.0.1:8006/records`，在记录列表点击某条记录的 **🔍 审核** 按钮，进入审核详情页。

**第三步：上传 OCR 文件（9 个槽位）**

| 槽位 | 文件类型 | 说明 |
|------|---------|------|
| 审批单 | 业务招待审批单 | 图片/PDF |
| 申请单 | 业务招待申请单 | 图片/PDF |
| 报账单 | 业务招待费报账单 | 图片/PDF |
| 发票 XML | 发票（XML 格式） | .xml 文件 |
| 发票 PDF | 电子发票（PDF 格式） | .pdf 文件 |
| 经营状态 | 招待单位经营状态 | 企查查截图等 |
| 支付凭证 | 支付凭证 | 图片 |
| 支付流水 | 支付流水证明 | 图片/PDF |
| 活动函件 | 活动函件 | PDF |

- 点击任一槽位卡片，弹出详情弹窗
- 弹窗中显示原图预览、OCR 原始文本、提取字段
- 点击弹窗底部的上传区域，选择文件上传
- 上传相同文件会自动跳过（去重），上传不同文件会覆盖旧文件

**第四步：字段提取**

点击 **字段提取** 按钮，系统从所有已有 OCR 文本中自动提取结构化字段：

| 槽位 | 提取字段示例 |
|------|------------|
| 审批单 | 招待日期、招待人数、陪同人数、人均费用、招待金额、招待类型、招待对象 |
| 发票 | 价税合计（大写/小写）、开票日期、购买方、销售方 |
| 支付凭证 | 交易单号、商户单号、金额、商户全称、支付时间 |
| 支付流水 | 交易单号、交易对方、金额、交易时间 |

**第五步：触发审核**

点击 **触发审核** 按钮，系统执行 6 条审核规则：

| 规则 | 严重程度 | 校验内容 |
|------|---------|---------|
| 金额一致性 | 高 | 发票金额 vs 审批单 vs 支付凭证 vs 支付流水 vs 报账单 |
| 日期一致性 | 高 | 审批单日期为基准，发票日期≤招待日期，支付日期≥招待日期 |
| 招待标准合规性 | 高 | 人均费用标准、陪同人数标准 |
| 单位经营状态 | 提示 | 模糊匹配单位名称，判断经营状态是否正常 |
| 支付凭证一致性 | 高 | 支付凭证 vs 支付流水：交易单号、金额、商户名称 |
| 活动函件日期 | 中 | 函件日期与招待日期相差 ±7 天内 |

**第六步：查看/下载报告**

- 审核结果实时展示在页面下方
- 点击 **下载报告** 按钮，下载 Markdown 格式的审核报告
